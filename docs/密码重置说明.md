# 管理员密码重置说明

适用于 Docker 部署的仓管系统。按下面顺序判断走哪条路，**能走前面的就不要动数据库**。

---

## 第 0 步：先确认部署模式

两条自助恢复路只在特定模式下开放，而镜像默认值和 compose 默认值是**相反的**：

| 位置 | 默认 `DEPLOY_MODE` |
|---|---|
| 镜像内置（`Dockerfile.prod:75`） | `single_tenant` |
| `docker-compose.prod.yml:50` | `multi_tenant`（compose 会覆盖镜像） |

所以不能靠猜，直接问系统：

```bash
curl http://<部署机IP>:2125/api/system/mode
```

---

## 路径 A：还有别的管理员账号能登录

最省事，不需要碰服务器。

用另一个 admin 账号登录 → 「设置 / 用户管理」→ 找到忘密码的用户 → 编辑，填新密码保存。

前提：操作者角色是 `admin`（后台接口要求 `USERS:ADMIN` 权限）。

---

## 路径 B：`multi_tenant` 模式 → 登录页自助「找回密码」

凭 **设备 ID + 管理员用户名** 就能自己重置，不需要任何后台介入。

界面：登录页 → 「注册 / 找回密码」→ 输入设备 ID → 系统识别出该设备已注册 → 进入「重置密码」步骤。

也可以直接调接口：

```bash
curl -X POST http://<部署机IP>:2125/api/auth/reset-password \
  -H 'Content-Type: application/json' \
  -d '{"device_id":"<设备ID>","username":"<管理员用户名>","new_password":"NewPass123"}'
```

限制：

- `DEPLOY_MODE` 不是 `multi_tenant` 时直接返回 403
- **限速 5 次/小时**（防止有人拿设备 ID 批量试）
- 成功和失败都会写审计日志，含来访 IP 和 User-Agent
- 目标账号必须是该设备所属租户下、角色为 `admin`、且未被禁用的账号
- 新密码要求：≥8 位、同时含字母和数字、不能是常见弱密码

设备 ID 在「设置 → 系统信息」里能看到；设备 ID 也丢了就只能走路径 C。

---

## 路径 C：单租户部署 / 设备 ID 也没了 → 在服务器上跑重置脚本

脚本：`scripts/reset_admin_password.py`（单文件，不依赖仓库里其它文件）。

它复用系统自己的密码哈希函数，写进去的格式和应用完全一致；连哪个数据库由容器里现成的环境变量决定，**SQLite 和 MySQL 两种后端都适用**，脚本不需要你填连接串。

### 操作步骤

```bash
# 1) 确认容器名（下面统一用 warehouse-prod，实际以这里看到的为准）
docker ps

# 2) 把脚本拷进容器
docker cp reset_admin_password.py warehouse-prod:/tmp/

# 3) 先列出所有账号，确认用户名（这一步只读，不改任何东西）
docker exec -it warehouse-prod /app/.venv/bin/python /tmp/reset_admin_password.py --list

# 4) 重置（会提示输入两遍新密码，密码不会留在命令历史里）
docker exec -it warehouse-prod /app/.venv/bin/python /tmp/reset_admin_password.py <用户名>

# 5) 用完删掉
docker exec warehouse-prod rm /tmp/reset_admin_password.py
```

第 3 步输出长这样：

```
[db] sqlite:////data/warehouse.db
  ID  用户名                  角色         租户                   状态
------------------------------------------------------------------------
   1  seeed                admin(管理员) 默认租户                 启用
```

第 4 步成功后：

```
完成。seeed(id=1) 的密码已更新，吊销会话 0 个。未重启容器，新密码对下一次登录生效。
RESET-RECORD: user_id=1 username=seeed tenant_id=1 enabled=False revoked_sessions=0 (本脚本不写应用审计日志，请自行留档)
```

改完不需要重启容器（每次登录都是现查数据库）。登录时应用还会检查账号是否禁用、所属租户是否停用、同名账号是否在多个租户下使用同一密码；这几种情况脚本会在重置前打印「警告」，未处理时登录仍会被拒绝。

### 常用参数

| 参数 | 用途 |
|---|---|
| `--list` | 只列账号，不做修改 |
| `--tenant-id N` | 同一用户名在多个租户下都存在时，指定是哪一个 |
| `--enable` | 顺便解除该账号的禁用状态 |
| `--password 'xxx' --yes` | 非交互模式（无 TTY 时用；注意密码会进 shell history 和 `ps`） |
| `--allow-weak` | 跳过密码强度校验，应急用；用完请尽快在界面里改成强密码 |

### 脚本的几条行为约定

- **同名不猜**：一个用户名在多个租户下都有账号时，脚本会把候选列出来并要求 `--tenant-id` 指明，不会随便挑一个改。
- **只改一行**：UPDATE 影响行数不等于 1 时直接报错退出，不会留下半吊子状态。
- **吊销旧会话**：与界面里改密一致，该用户所有未吊销的登录会话在同一事务里标记为已吊销，已登录的浏览器需要用新密码重新登录。`RESET-RECORD` 里的 `revoked_sessions` 是本次吊销的会话数。
- **账号禁用会警告**：目标账号处于禁用状态且未加 `--enable` 时，打印警告"登录会被拒绝（用户已被禁用）"。
- **租户停用会警告**：目标账号所属租户 `is_active` 为假时，打印警告"登录会被拒绝（租户已停用）"。脚本不修改租户状态。
- **同名账号会警告**：同一用户名在其它租户下还有启用中的账号（且该租户未停用）时，打印警告"同名账号在多个租户存在，若密码相同登录会被拒绝"。给该账号设一个与其它同名账号不同的密码即可避开。
- **口令不外泄**：打印数据库地址时会把 MySQL 连接串里的密码打码成 `***`。
- **不写应用审计日志**：`docker exec` 跑在应用进程之外，写了也不会进 `docker logs`。脚本会打印一行 `RESET-RECORD`，请自行留档。

### 可能遇到的问题

**`docker compose exec` 找不到服务**
部署目录名和 compose project 名不一致时会这样。用 `docker ps` 看到的**实际容器名**配 `docker exec` 最稳，绕开 project 名的问题。

**提示"找不到 backend 目录"**
说明不是在容器里跑的，或者镜像布局不是标准的 `/app/backend`。用环境变量指定：

```bash
WAREHOUSE_BACKEND_DIR=/app/backend /app/.venv/bin/python /tmp/reset_admin_password.py --list
```

**提示"导入依赖失败"**
用错解释器了。必须用 `/app/.venv/bin/python`，容器里的系统 `python` 没装 sqlalchemy / bcrypt。

**提示"当前没有 TTY"**
`docker exec` 忘了带 `-it`。补上，或者改用 `--password 'xxx' --yes` 非交互模式。

**MySQL 部署时不要去改 `/data/warehouse.db`**
`.env` 里填了 `DATABASE_URL` 时，`/data` 卷里的 SQLite 文件是闲置的，改它没有任何效果。脚本走 `get_engine()` 会自动连对，按上面步骤操作即可，无需关心这一点。

---

## 事后建议

- 用 `--allow-weak` 应急设过的弱密码，登录后立刻在界面里改成强密码。
- 单租户部署没有任何自助找回通道，建议**保留至少两个 admin 账号**，避免下次又要上服务器。
- 脚本用完从容器里删掉，别长期留在 `/tmp`。
